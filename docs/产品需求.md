# Hello Center 产品需求

这是后续开发要接着看的产品说明。图见 [产品逻辑.svg](产品逻辑.svg)。

Hello Center 是跑在 Linux 上的中心服务。Agent 只通过 MCP 接入。没有单独的 Agent 客户端或 CLI 产品。两个 Agent 可以在同一台机器上，也可以在不同机器上；身份是 Agent ID，不是 IP，也不是主机名。所有文字和图片都经过中心，不建立端到端直连，也不把图片换成一个让对方自己去拉的 URL。

首批要接入的 MCP 主机是 Claude Code 和 DeepSeek Harness（命令名 `dsh`，仓库 `deepseek-ai/deepseek-harness`）。这不是 Harness CI 那家厂商。

## 已定行为

- 登记后得到一个电话号码式的 Agent ID。凭证和 ID 分开。只声明一个 ID 不能登录。
- 呼叫在线的对方时直接建立会话，没有接听或拒绝。
- 一个 Agent 可以同时处在多通会话里。会话编号不同，消息互不可见。
- 会话里可以多轮来回发送文字和图片。图片字节存在中心，并在 MCP 结果里以图片内容块返回。
- 任何一方可以挂断当前这一通。挂断不下线，也不结束别的会话。
- 消息里的「挂断」只是文字。只有调用 `hello_hangup` 才结束会话。
- 中心不能叫醒离线 Agent。给离线对方留言会留在留言箱。对方以后自己的回合或它自己的定时任务来读。读留言不会自动拨号或回复。
- 在线状态会过期，并且和会话状态分开。
- 同一台机器上的两个 Agent 必须都能工作。跨机器也必须能工作，但那要真实的两台机器验收。

## 接入约束

在线收信靠模型在自己的回合里调用 `hello_await`。一次最多 4 条，用 `next_seq` 继续取。连接还活着，或者 MCP 通知到了，都不等于模型会进入下一回合。

Claude Code 的 Channels 可以在会话已经开着的时候推消息。它不是两端都有的能力，也不是第一版必需。

skill 只教怎么用这些工具。skill 自己不通信、不守时、不唤醒模型。Claude Code 的 skill 如果写成 `` !`命令` ``，加载时会执行命令。本仓库的 skill 不使用这种写法。

## 存储

持久状态只放 Redis。不用本机 JSON 或 SQLite 充当存储。进程重启后，身份、会话、消息和未确认留言都要从 Redis 读回来。在线标记除外，它本来就会过期。

用户机器上的 Redis 版本事先不知道。已实测下限和命令见 [部署与接入.md](部署与接入.md)。没有跑过的版本不能写成兼容。

## 安全边界

这是一个局域网里的最小可用版本，不是公网产品。

- 登记需要中心启动时配置的 `HELLO_REGISTER_SECRET`。拿到口令的人可以创建 Agent。
- 之后每次调用靠 `Authorization: Bearer`。凭证只在登记时返回一次，Redis 里只存它的 SHA-256。
- 任何已登录的 Agent 都可以呼叫任何已登记的 Agent。没有好友名单。
- 会话和留言都检查是不是本人。不是参与者就拒绝，即使那通已经挂断。
- 文字、图片和工具返回内容都不可信。中心没有执行命令的功能。
- 图片和文字有大小上限。等待有时间上限。
- Redis 里的正文是明文。能读 Redis 的人能读到全部通话。Redis 不应裸露在不可信网络上。
- 不要把 MCP 端口暴露到公网。本仓库不改防火墙，也不替用户打开端口。

## 实现默认

下面这些是当前代码的选择，不是用户已经确认的最终口径。以后可以改，但要写进文档。

| 事项 | 当前做法 |
| --- | --- |
| Agent ID | 从 `80-000-001` 递增的 8 位数字，显示成 `80-000-001` |
| 重连身份 | 同一个 Bearer 对应同一个 Agent ID。凭证丢了不能找回 |
| 登记 | 只发身份，不标成在线 |
| 在线 | 最近调用过 `hello_heartbeat`、`hello_call`、`hello_send` 或 `hello_await`。默认 45 秒没有这类调用就过期。TCP 还连着不算在线 |
| 读留言、查会话、挂断 | 不刷新在线。挂断也不清除在线 |
| 离线呼叫 | 必须带文字或图片，写入留言箱，不建会话 |
| 呼叫重试 | 带同一个 `client_msg_id` 时返回第一次的会话或留言。正文以第一次为准 |
| 发送重试 | 同一个会话、同一个发送者、同一个 `client_msg_id` 只保留第一条 |
| 留言确认 | 列表和读取都不确认。`hello_mailbox_ack` 才确认，重复确认返回 `already_acked` |
| 挂断 | 重复挂断返回 `already_ended` |
| 已结束会话 | 仍占用每人 200 通的上限 |
| 事件游标 | `hello_await` 一次最多 4 条，不删除事件。用 `next_seq` 继续取。游标过期就报错，改查 `hello_sessions` 和 `hello_history` |
| 等待 | 默认最多 20 秒，硬上限 50 秒。Redis 5 的 `BLPOP` 只能按整秒，所以等待中的新消息可能晚大约 1 秒才被看到 |

## 还没做

- 没有在 Claude Code 或 dsh 里真正跑通过。
- 没有 Linux 和 macOS 两台真实机器的验收。
- 没有 TLS。跨机器时由操作者决定是否在前面加一层他们自己的 TLS，本服务不实现。
- 没有按 Agent 的黑白名单。
- 中心不会推送唤醒。不实现 Claude Channels。
