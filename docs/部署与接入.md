# 部署与接入

## 这台验证机上的版本

| 组件 | 版本 |
| --- | --- |
| 操作系统 | Linux 6.12.113+ x86_64，glibc 2.39。这是云端虚拟机，不是用户的电脑，也不是 macOS |
| Python | 3.12.3 |
| mcp | 2.3.0 |
| redis-py | 8.1.0。默认会用 RESP3 的 `HELLO`，并可能发 Redis 7.2 才有的 `CLIENT SETINFO`。本服务强制 `protocol=2`，并关闭 `driver_info` |
| Redis | 用官方源码、`make MALLOC=libc` 编译后实测：5.0.14、6.2.18、7.2.11 |

已实测下限是 **Redis 5.0.14**。比这旧的版本服务会拒绝启动。比这新、但不在上面三个版本里的 Redis 可以启动，日志会写明「这不是兼容性结论」。不要把没跑过的版本写成可用。

Redis 6 的 ACL 用户名没有测。测过的是 Redis 5.0.14 上的单密码 `AUTH`：`redis://:密码@127.0.0.1:6379/0` 可以 `PING` 和 `SET`。完整通话验证时 Redis 没有设密码。

## 实际使用的 Redis 命令

`PING` `INFO` `AUTH` `SET` `GET` `DEL` `EXISTS` `INCR` `EXPIRE` `TTL` `HSET` `HSETNX` `HGET` `HGETALL` `LPUSH` `RPUSH` `LTRIM` `LRANGE` `LLEN` `LREM` `SADD` `SMEMBERS` `SCARD` `EVAL` `BLPOP`

不用 Streams、`HELLO`、Functions、JSON 模块、`HEXPIRE`、ACL。`EVAL` 里用了 Redis 自带的 `cjson`，5.0.14 上可用。`BLPOP` 的超时只用整数秒，因为 Redis 5 不接受小数。

不支持 Redis Cluster。键名没有 hash tag。

## 持久化

验证时使用 `--appendonly yes --appendfsync always`。在这种设置下，进程被 `SIGKILL` 之后，用同一数据目录再启动，Agent ID、会话里的图片和未确认留言都还在。

`scripts/run_redis.sh` 使用 `appendfsync everysec`。这种设置理论上可能丢掉大约一秒内的写入。要和验证一样稳，把 `everysec` 改成 `always`。

## 安装与启动

需要 Python 3.12。依赖声明写过 `mcp` 需要 3.10 或更新，但这次只在 Python 3.12.3 上安装和运行过，没有在 3.10 或 3.11 上试过。请用 Python 3.12。

`redis-server` 用你机器上的可执行文件，不要照抄验证机的临时路径。先看它在哪：

```sh
command -v redis-server
redis-server --version
```

数据放在当前用户能写的新目录，例如 `$HOME/hello-redis`。不要默认放到 `/var/lib`，那通常要 root。

6379 上如果已经有 Redis，不要再启动第二份去占同一个端口。已有实例就继续用它，并把下面 env 文件里的 `HELLO_REDIS_URL` 改成那个地址。没有现成实例时才执行 `run_redis.sh`。

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
scripts/init_local_env.sh
mkdir -p "$HOME/hello-redis"
scripts/run_redis.sh "$(command -v redis-server)" "$HOME/hello-redis" 6379
scripts/run_center.sh
```

`init_local_env.sh` 用 `umask 077` 生成 `config/hello-center.env`。登记口令只在这个文件里，权限是 600，脚本不打印口令。不要写进 shell 历史，也不要提交。模板 `config/hello-center.env.example` 里的口令是空的。`run_center.sh` 在环境变量没设时会读这个文件。

启动失败时退出码是 2。没设登记口令、配置不合法、连不上 Redis、Redis 旧于 5.0.14，都是 2。版本太旧或连不上时，日志里不会先出现「监听」。stderr 里有原因。

Redis 连接写在 `HELLO_REDIS_URL`。本机无密码时是 `redis://127.0.0.1:6379/0`。有密码时只改已被 git 忽略的 `config/hello-center.env`，格式 `redis://:密码@127.0.0.1:6379/0`。不要写进 `config/hello-center.env.example`。

中心监听 `http://127.0.0.1:8731/mcp`。给局域网里别的机器用时，把 `HELLO_BIND` 设成那块网卡的地址，并设置 `HELLO_ALLOWED_HOSTS`（例如 `192.0.2.10:8731`），否则 DNS 重绑定检查是关的。只在可信局域网里开放这个端口。不要暴露到公网。本仓库不会修改防火墙。

### 两个 Agent 的凭证

中心起来之后，每个 Agent 登记一次。下面的命令只在标准输出打印 Agent ID，Bearer 写入权限 600 的文件：

```sh
set -a; . ./config/hello-center.env; set +a
.venv/bin/python scripts/register_once.py --token-file config/agent-a.token --display-name 甲
.venv/bin/python scripts/register_once.py --token-file config/agent-b.token --display-name 乙
```

`register_once.py` 的标准输出只有一行 Agent ID，例如 `80-000-001`。没有 JSON，也没有 token。token 在你指定的文件里，权限 600。

`config/*.token` 已被 git 忽略。装入某个 Agent 的进程时不要打印文件内容。在准备启动那个主机的终端里执行，`exec` 会替换掉这个子 shell，父终端不会留下变量：

```sh
(
  IFS= read -r HELLO_AGENT_TOKEN < config/agent-a.token
  export HELLO_AGENT_TOKEN
  exec 这里换成该 Agent 的主机启动命令
)
```

第二个 Agent 换一个终端，读 `config/agent-b.token`。不要 `echo`、`cat` 或把变量写进命令历史。不要提交这些文件，也不要贴进对话或日志。

Claude Code 使用 `examples/mcp/claude-code.mcp.json`，头是 `Authorization: Bearer ${HELLO_AGENT_TOKEN}`。登记那一次才用 `examples/mcp/claude-code-register.mcp.json`，头是 `X-Hello-Register-Secret`，值来自 `HELLO_REGISTER_SECRET`，同样用环境变量，不要写进仓库。登记完成后关掉这份配置，改用 Bearer。

dsh 的条目在 `examples/mcp/dsh-entry.yaml`。字段来自 `@deepseek-ai/dsh-mcp-client` README。官方示例 `examples/mcp-memory/README.md` 把同样的字段放在 `insert:` 下面。两个页面都没有写死本机文件名，所以这里不猜。两个 Agent 是两个 dsh 进程、两个 token 文件。没有在 dsh 里加载过。图片要进对话，还得当前模型接受图片并且 attachment 开着；否则只给诊断文字。这个条件来自 README，不是本次实测。

同一台机器上先确认协议时，可以跑：

```sh
scripts/minimal_accept.sh /path/to/redis-server
```

它会自己再起一个 Redis 和中心，默认端口是 56479 和 8741，不是 6379。已有 Redis 时它不会去占 6379；如果 56479 已经被占用，先设置 `HELLO_REDIS_PORT` 再跑。脚本结束时会关掉自己启动的那一份。输出里没有口令。这仍然是本机独立进程，不是 Claude Code、dsh 或跨机器。

主要环境变量还有：`HELLO_PRESENCE_TTL`（2 到 300，默认 45）、`HELLO_AWAIT_MAX_MS`（最大 55000，默认 50000）、`HELLO_MAX_IMAGE_BYTES`（最大 512 KiB）、`HELLO_MAX_TEXT_BYTES`。

## 重复验证

```sh
.venv/bin/python scripts/verify_e2e.py --redis-server /path/to/redis-server
scripts/redis_matrix.sh /path/to/redis-5.0.14 /path/to/redis-6.2.18 /path/to/redis-7.2.11
```

编译当时用过的三个版本：

```sh
curl -fsSL -O https://download.redis.io/releases/redis-5.0.14.tar.gz
tar -xzf redis-5.0.14.tar.gz
make -C redis-5.0.14 -j"$(nproc)" MALLOC=libc
./redis-5.0.14/src/redis-server --version
```

6.2.18 和 7.2.11 同样处理。`redis-server --version` 的输出分别是 `v=5.0.14`、`v=6.2.18`、`v=7.2.11`。

## Claude Code

语法对照的是 2026-11-10 的官方文档 [Connect Claude Code to tools via MCP](https://code.claude.com/docs/en/mcp)。没有在 Claude Code 里执行。

项目里的 `.mcp.json` 必须带 `type`。只有 `url` 会被当成 stdio 而跳过。`type` 用 `http`；文档写明 `streamable-http` 是它的别名。远程服务用 `headers`，`${变量}` 会在运行时展开。

```json
{
  "mcpServers": {
    "hello-center": {
      "type": "http",
      "url": "http://192.0.2.10:8731/mcp",
      "headers": {
        "Authorization": "Bearer ${HELLO_AGENT_TOKEN}"
      }
    }
  }
}
```

同一页说明：有些凭证变量名在发给远程服务器时会被读成空字符串，例如 `ANTHROPIC_AUTH_TOKEN`。所以这里用 `HELLO_AGENT_TOKEN`，不要用那类名字。

登记用另一份配置，头是 `X-Hello-Register-Secret`。见 `examples/mcp/`。登记得到的 token 交给操作者写入 `HELLO_AGENT_TOKEN`，然后重新开一个会话。

skill 放在仓库的 `skills/hello-center/SKILL.md`。Claude Code 官方说明的项目路径是 `.claude/skills/<名字>/SKILL.md`（[skills 文档](https://code.claude.com/docs/en/skills)）。本仓库用符号链接把 `.claude/skills/hello-center` 指到那份 skill。链接本身没有在 Claude Code 里加载过。

同一台机器上的两个 Agent，就是两个 Claude Code 进程，两份配置，两个 token。都连同一个中心 URL。

## DeepSeek Harness（dsh）

官方项目是 [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)，文档站是 <https://deepseek-harness.github.io/deepseek-harness/>。它不是 Harness CI。

`@deepseek-ai/dsh-mcp-client` 的 README（master）写明传输只有 `stdio` 和 `streamable-http`。远程条目是：

```yaml
- id: mcp-hello
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: hello
    transport: streamable-http
    url: http://192.0.2.10:8731/mcp
    headers:
      Authorization: !!js '`Bearer ${process.env.HELLO_AGENT_TOKEN}`'
    toolCallTimeoutMs: 60000
```

`serverName` 要匹配 `[A-Za-z0-9_-]{1,32}`。工具名会变成 `mcp__hello__hello_call` 这种形式。默认单次工具超时 60 秒，所以中心把 `hello_await` 限制在 50 秒以内。

README 还写明：MCP 结果里的图片，只有当前模型接受图片、并且 attachment 打开时，才会进入对话；否则模型看到诊断文字。PNG、JPEG、WebP、GIF 在这个前提下可以进入。本仓库没有跑 dsh，所以这只是文档，不是实测。

README 给出的是插件条目，没有在这次核对里确认它该写入哪个文件。社区讨论里提到过 `cordis.yml`，那不是 README 的路径说明，不能当成已核实。dsh 的 skill 目录这次没有从官方页面读到正文，所以不写安装路径。可以把同一份 `SKILL.md` 交给操作者，等核对过 dsh 当前的 skill 文档再放。

## 主机调度的限制

两边共同的底线是拉取，不是推送。

- 模型只有在一个回合里才能调用 `hello_await` 或读留言。
- 中心不会因为你在线就把下一句话送进模型。
- Claude Code 可以用用户消息、`/loop`、定时任务或 `claude -p` 再开一个回合。这些都是主机自己的调度。Channels 只对已经开着的会话有意义，第一版不依赖它。
- dsh 可以用 `dsh web` 的交互，或 `dsh headless` 这种跑完就退出的任务去查留言。README 没有承诺 MCP 通知会打开一个新的回合。
- 如果没有人安排下一次运行，Agent 就会一直离线，留言会留在 Redis 里。
